# 28-jsvmp2 解释器分型

切片只做解释器形态。不填 opcode 语义，不改字节码，不做 opcode 验收。知识边界来自 `article/web-reverse/jsvmp-custom-isa-interpreter-reference.md`：该文没有 opcode 表；教学样本的「一字符一字节、低位在前」不用于本题。静态 `switch` 的 case 数不是覆盖率。

依据是静态阅读 `challenges/28-jsvmp2/assets/jsvmp2.js` 与 `assets/sdk.min.js`。没有新的 RuyiTrace，也没有带操作数或栈值的 Trace。因此不能判断静态解释器与运行时解释器是否一致。

## 机器

栈机器。操作数栈是一个数组，栈指针自增为压入、自减为弹出。页面脚本这段循环里，压入形态 33 处、弹出形态 35 处。至少一条路径从栈上取两个槽做二元运算，再把结果写回栈槽。立即数路径是再读一个字节码元素、解码后压栈，不是写入独立寄存器。

没有看到与操作数栈分开的通用寄存器组。取指用的 8 比特滚动量只参与解码，不算寄存器文件。

页面脚本和 Worker 脚本各有一台同形栈机。下面的「页面 / Worker」分别指这两份本地快照，不表示请求已经接到其中一台。

## 状态

解释循环能对上的部分：进入 `while (1)`，用程序计数和字节码数组长度做退出检查，取一个元素，解码，查表，比较分发，再改栈。

| 状态 | 页面脚本 | Worker 脚本 | 依据 |
|---|---|---|---|
| 虚拟程序计数 | 下标字节码数组，每取一个元素加一；读到长度则离开循环 | 同形 | 主取指一处，另有再读一个元素的路径 |
| 栈指针 | 与程序计数不是同一个变量 | 同形 | 压入/弹出成对出现 |
| 滚动量 | 8 比特，每解码一个元素后更新 | 同形 | 见编码 |
| 寄存器文件 | 未看到 | 未看到 | 缺口 |
| 调用栈、当前帧 | 未与操作数栈分开 | 未与操作数栈分开 | 缺口。外层 `with` 换的是混淆包装的对象，不是这台栈机的帧 |

外层包装是另一套状态：`while` 的条件是两个、三个或四个数值状态之和，不等于某个退出常数；`switch` 的判别式是同一个和；`with` 在对象之间换当前对象。页面脚本这种和式循环 28 处，Worker 脚本 26 处。这是状态选择包装，不是采集框架里的调度器，也不是 opcode 分发。

## 分发

主分发是表驱动，不是 `handlers[op]()`，也不是线性一次派发。

1. 字节码数组的当前元素与滚动量异或。
2. 异或结果作为下标，读一张 `Int16Array(256)`。
3. 表项为 `-1` 时抛出字符串池里的 `Illegal Opcode`。页面池下标是 99，Worker 池下标是 91，两套池不能混用。
4. 表项不是 `-1` 时，用嵌套比较选择动作。比较之后没有函数指针表。

表的初始化两份脚本各一处，且源码顺序不等于执行顺序：先 `fill(-1)`，再用一个排列把一段连续序号写进 256 槽。两处循环上界相同。这个上界只说明初始化写过哪些槽，没有第二套运行时计数，不记成 opcode 条数或覆盖率，不列出序号含义。没有核对这张表在运行中是否被改写；按参考只记「若动态改映射会增加组合」，不记组合数字。

外层和式 `switch` 是状态选择，包住包括这段 `while (1)` 在内的大量代码。不要把外层 case 数当成指令覆盖率。

## 池

字符串池有。构造是 `decompressFromUTF16` 再按 `|` 拆开，取值函数按下标返回。页面池 3301 项，Worker 池先前清点为 1826 项。页面池里 3166 项以 `@` 加十六进制字母开头，字母表只有 `0-9a-f`，长度多为偶数。这些字面量前后没有第二份对照，不采用为字节码布局，也不当成 opcode 表。

常数池：没有看到与字符串池分开的数字池。立即数出现在字节码流上。记缺口。

函数表：opcode 映射是 `Int16` 序号表，不是函数指针表。混淆包装层另有按解码字符串缓存函数的对象，未证明它是这台栈机的函数表。解释器窗口里出现过 `call` / `apply` 这些池字面量，没有据此重建调用约定。

## 编码

主取指的宽度依据是 8 比特，不是教学文的字符编码：

- 解码值用来下标长度为 256 的表，非法哨兵是 `-1`。
- 滚动量更新写成 `(旧量 ^ 解码值) + 2 * (旧量 & 解码值)` 再 `& 255`。这个式子等于 `(旧量 + 解码值) & 255`。
- 更新发生在程序计数加一的同一处。

端序：主取指没有多字节装入，没有 `DataView`。端序是缺口。同文件里的 `compressToUint8Array` 把一个码元拆成高字节在前、低字节在后，那是 LZ 辅助函数，不是这台栈机的操作数编码。

操作数宽度：部分路径在主取指之外再读一个数组元素，仍走同一套异或和滚动量，然后压栈。只证明「有的路径再消费一个元素」。没有逐条核对立即数宽度，不采用 2、4 或 5 这一类教学宽度。

## 缺口

- 目标参数的 VM 入口。
- 多字节端序，以及逐指令的立即数宽度。
- 调用栈、当前帧、独立常数池、VM 函数表。
- 映射表是否在运行中改写。
- 静态解释器与运行时解释器是否一致。
- opcode 语义。初始化循环上界不作为条数。

## 停止

分型写完仍不能做 opcode 验收。没有带操作数或栈值的 Trace 和 fixture。不要把 `opcodeEvidence=true` 当成 gate。本切片不跑 `web_case.py`。
